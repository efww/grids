# 인수인계 - 계장 개념설계 I/O 리스트 산출 도구 (pid_io v4)

새 채팅에서 이 문서를 먼저 읽고 시작하세요. (작성: 2026-11-25)

## 1. 한 줄 요약

P&ID **벡터 PDF**에서 계기 심볼과 태그를 자동 인식하고, **개념설계 체크리스트(설계 가정)**를 적용해 회사 양식의 Instrument Index와 IO 물량을 산출하는 로컬 웹앱입니다. 레퍼런스 인덱스 없이 동작하며, 레퍼런스는 채점용입니다.

## 4. 핵심 설계 원칙 (바꾸지 말 것)

1. **사실과 가정의 분리**: 도면 인식은 항상 전부 수행하고, IO를 바꾸는 것은 체크리스트뿐입니다.
2. **IO 1점 = 인덱스 1행**: 배수나 파생 IO도 모두 행으로 만듭니다. 산출구분은 6종입니다(도면인식 / Typical파생 / 트레인복제 / 장비Typical / 패키지 / 스페어). 근거 열에 시트, 노트, 체크리스트 ID를 남깁니다.
3. **Typical은 체크리스트 엑셀의 `Typical_Points` 시트가 단일 정의**입니다. 엔진과 엑셀 요약 수식이 같은 표를 씁니다.
4. **AI는 제안만 합니다.** 사람이 승인해야 `overrides.json`에 저장되고 반영됩니다.
5. **오프라인 우선**: 외부 통신은 AI를 켤 때만 합니다.

## 5-1. IO 판정 원칙 (사용자와 합의)

- IO는 **기능코드 개념 규칙이 주 판정**입니다(전송기 AI, 제어밸브 AO, 솔레노이드 DO, 스위치 DI).
- 신호선 종류와 화살표는 **보조 근거**입니다. 개념설계 도면은 화살표·선 종류가 불완전하기 때문입니다.
- 불일치는 자동으로 고치지 않고, 검토 화면과 AI 판단을 거쳐 사람이 승인합니다.
- 이번 도면: 현장 계기 241개 중 일치 71, 불일치 0, 근거 없음 170. 추출 시간은 약 106초로 늘었습니다.

## 5-2. v4에서 추가된 것

- **신호선 보조 판정** (`signals.py`): 결과는 일치·불일치·근거 없음 세 가지이고, 불일치만 검토와 AI 판단으로 넘깁니다. 이번 도면: 일치 71, 불일치 0, 근거 없음 170
- **판단 카드** (`markup.py`): 빨강은 판단 대상, 주황은 신호선, 파랑은 도착 심볼, 보라는 벤더 경계입니다. 검토 썸네일과 AI 질문 이미지에 씁니다.
- **판단 요청서 PDF** (`review_packet.py`): 카드, 질문, 체크박스를 A4 한 장에 4건씩 담습니다. 이번 도면은 44건입니다.
- Interlock 연결 추정이 신호선으로 확인되면 "추정"을 해제합니다.
- 인덱스 엑셀에 **적용_체크리스트** 시트를 추가했습니다(기존 Concept_Basis 대체). 항목별로 적용값, 반영 상태, 생긴 행·IO, 다른 선택 시 IO 변화를 보여줍니다.
- **인덱스 열 결정사항 목록**(`인덱스_결정사항.xlsx`)을 사용자에게 전달했습니다. 사용자가 하나씩 결정하면 그 결정에 맞춰 구현하면 됩니다.

## 7. 알려진 한계

- 기준값(원 반지름 9~26pt, 글자-번호 간격 5~27pt, coverage 0.85·0.9)이 이 도면에 맞춰져 있습니다. 다른 축척의 도면에서 깨질 수 있습니다.
- 레전드 자동 학습은 미구현입니다. 지금 읽는 건 벤더 경계 선 두께뿐입니다.
- 태그는 "글자 위 / 번호 아래" 형식만 인식합니다. 한 줄 태그나 회전 텍스트는 놓칩니다.
- ESD 판정은 Interlock 심볼 연결에만 의존합니다. 액추에이터에서 끊긴 선은 가장 가까운 밸브로 추정합니다.
- 같은 태그는 하나로 합칩니다(B10으로 바꿀 수 있음). 장비는 P-(펌프)와 PK-(패키지)만 인식합니다.
- 빈 열: Service Description, Line No, Line Size, Equipment No, Area, IS
- 승인한 판단(overrides)이 좌표 기반 키로 저장됩니다. 리비전이 바뀌면 유실될 수 있습니다.
- 자동 테스트가 없습니다. 스캔 PDF는 미지원입니다.
- **AI**: Copilot CLI 옵션이 미확인입니다(설정 화면의 명령 템플릿으로 조정). 실제 모델로 돌려 보지 않았고, CLI에는 이미지가 전달되지 않습니다. 설명서 AI 화면의 답변은 시연용 가짜 CLI 결과입니다.

## 8. 다음 단계 (사용자와 합의된 방향)

1. **과거 프로젝트 정답지로 학습·검증**: 사용자가 레전드가 포함된 P&ID와 정답 인덱스를 여러 개 보유하고 있습니다.
   - ① 자동 채점기: 태그 기준 대조로 프로젝트별 재현율·정밀도를 내고, 회귀 테스트로 씁니다.
   - ② 기준값과 IO 관행 자동 보정: 놓친 태그 위치의 지문을 재서 맞춥니다.
   - ③ 심볼 지식베이스와 작은 분류 모델, AI 질문 시 과거 예시 제공
   - 조건: 정답지에 실제 태그 번호가 있어야 하고, 도면과 리비전이 같아야 합니다. 스타일이 다른 프로젝트 2~3개로 시작합니다.
2. 미적용 체크리스트 항목 구현 (HOLD·FUTURE 인식, 팬 등 장비, 장비리스트 연동)
3. Line No / Service Description 채우기 (배관 추적, AI)
4. 리비전 비교 (Rev 증감 리포트), 승인 판단을 태그 기반으로 저장
5. AI: 사용자가 GitHub Copilot 유료 결제 후 회사 PC에서 `copilot --help`로 옵션을 확인하고 연결 테스트를 해야 합니다. 회사 M365 Copilot은 API가 없어서 수동 브리지로 씁니다.
